# NCU Navigator

Campus navigation website: search any room, see it on the floor plan, and get
step-by-step directions across floors and buildings.

The site is campus-agnostic. A campus is a data file (`data/<id>.json`); the code
never mentions a particular college. Two campuses are bundled: the NCU dummy layout
and a fictional "Greenfield" campus with a different shape.

## Run it

Needs only Node 18 or newer. There is nothing to install.

```
node server/server.js
```

Open http://localhost:3000. On first start the terminal prints the admin email and
password. Set your own with environment variables:

```
ADMIN_EMAIL=you@college.edu ADMIN_PASSWORD=choose-a-strong-one node server/server.js
```

You can also double-click `index.html`. That is demo mode: no accounts, and every
change stays in that browser.

## Put it online

Any host that runs Node works (Render, Railway, a VPS).

- Start command: `npm start`
- Environment: `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `TOKEN_SECRET` (a long random string),
  and `DATA_FILE` pointing at a persistent disk (for example `/data/db.json`)

The database is one JSON file. On hosts that wipe the disk on every deploy, attach
a persistent volume and point `DATA_FILE` at it, or accounts and admin changes are lost.
For a larger rollout, swap the `persist()` function in `server/server.js` for a real database.

The outer campus map of NCU (`data/ncu.js`, generated by `tools/gen_data.py`) is the default map. A picture of it is in `assets/ncu-campus-map.png`.

## Features

- Interactive map: drag, pinch or scroll to zoom, building and floor switcher, icons per place type
- Search by room number, name, type or faculty; category tiles
- Plain-language search: `105 to N207`, `nearest washroom`
- Shortest route across floors and buildings, with turn-by-turn steps, time and distance.
  The Old and New buildings are joined by a bridge on every floor (ground to third); the router uses it like any other path
- Step-free mode (lifts only) and "nearest washroom / cafe / lift / medical"
- QR checkpoints: every place has a QR code (`#at-<placeId>`); scanning it sets the visitor's location.
  Manage has a printable sheet of all codes on a floor. The generator is built in (`js/qr.js`), no internet needed
- Shareable links to a place (`#p-<placeId>`) and to a route (`#r-<from>--<to>`)
- My classes: add a timetable, see the next class, one-tap directions
- Events pinned to places
- Favourites and recently viewed
- Accounts: students sign up; classes, favourites and location follow the account
- Admin: mark stairs/lifts out of service, rename a place or change its type,
  add and remove events and faculty, import another campus, change account roles.
  Admin changes are visible to every visitor
- Light and dark theme, phone layout with a bottom sheet

## API

| Route | Who | What |
|---|---|---|
| `POST /api/auth/register`, `/api/auth/login` | anyone | returns `{ token, user }` |
| `GET /api/me` | signed in | current account |
| `GET/PUT /api/me/data/:campus` | signed in | favourites, classes, location |
| `GET /api/campus/:id/state` | anyone | shared admin changes |
| `PUT /api/campus/:id/state` | admin | save edits, closures, events, faculty |
| `GET /api/campuses`, `GET /api/campuses/:id` | anyone | campus packages |
| `POST /api/campuses`, `DELETE /api/campuses/:id` | admin | import / remove a campus |
| `GET /api/users`, `PUT /api/users/:id` | admin | list accounts, change role |

Passwords are hashed with scrypt. Tokens are HMAC-signed and last 7 days. Sign-in is rate limited.

## Campus file format

```
{
  "id": "ncu", "name": "...", "shortName": "NCU",
  "layers":   [{ "id", "name", "short", "kind": "outdoor"|"floor", "building", "level",
                 "width", "height", "mpu" (metres per map unit), "shapes": [...] }],
  "buildings":[{ "id", "name", "short", "floors": [layerId, ...] }],
  "places":   [{ "id", "name", "label", "type", "layer", "node", "x", "y", "w", "h",
                 "door": [x, y], "number", "desc", "hours" }],
  "nodes":    [{ "id", "layer", "x", "y" }],
  "edges":    [{ "a", "b", "kind": "walk"|"stairs"|"lift"|"door"|"bridge", "m" (bridge length in metres), "conn" }],
  "connectors":[{ "id", "name", "building", "kind" }],
  "faculty":  [{ "name", "dept", "role", "place" }],
  "events":   [{ "title", "place", "date": "YYYY-MM-DD" or "inDays": n, "time": "HH:MM", "desc" }]
}
```

To add a real campus: describe its buildings in `tools/gen_data.py`, run it, and add a
`<script src="data/<id>.js">` line in `index.html`. Or sign in as admin and import the
JSON from the Manage tab without touching code.

## Known limits

- No live indoor positioning. Location is set by "I am here" or by scanning a QR checkpoint.
- Buildings are generated as rectangular blocks: rooms around a corridor ring with a courtyard in the middle.
- Faculty and events start as sample entries.
- The outdoor layout follows two hand sketches of the campus (not to scale); the room layout inside is a dummy, only the room numbering follows the real campus.
- Outdoor names taken from the sketches: Ground, Amphitheatre, Parking, Cafe 10, Labs lane with Nescafe, Court, Volleyball / Badminton Court, Sports Room and a Washroom. Edit them in Manage or in `tools/gen_data.py`.
- No password reset or email verification yet.

## Everyday features

| Feature | Where | Notes |
|---|---|---|
| **Time to leave** | Classes tab, home screen | Counts real walking time (stairs, lifts, bridges, step-free mode) from your location to the next class. Chains classes room to room. Optional reminder while the page is open. |
| **Upload my weekly timetable** | Classes tab | CSV or pasted text. Reads the university grid (`MON..Sa` rows, one column per period, cells like `MCL501 Neha RN 102`) and a plain list (`day,start,end,subject,room`). Fills day, time and room by itself. Photos and PDFs need OCR and are not read yet. |
| **Free rooms** | Free now tab | Rooms with nothing booked right now (or at a picked time), nearest first, filter by time left and building. |
| **Faculty status** | Explore, Faculty | Teaching (with room), in cabin, lunch, on leave, or away, from the timetable. Admins can mark someone on leave for today. |
| **Hinglish and Hindi search** | Search bar | `library kidhar hai`, `105 se N207 tak`, `sabse paas washroom`, Devanagari too. |
| **Voice search** | Mic in the search bar | Browser speech recognition (Chrome, Edge, Safari). Reads routes aloud too. |
| **Hindi interface** | Header button | Place names and room numbers stay as the campus file spells them. |
| **Offline app** | Install from the browser | Service worker caches the whole site and the maps. Needs https (or localhost). |

The weekly room timetable lives in the campus file (`timetable`, plus an optional `calendar` with open days, hours and lunch). The bundled data is generated sample data; admins replace it from Manage with a CSV (`room,days,start,end,subject,faculty`).

Tests: `node tools/test_core.js`, `node tools/test_i18n.js`, `node tools/test_server.js`, `python3 tools/test_ui.py`, `python3 tools/test_ui_features.py`, `python3 tools/test_ui_server.py`, `python3 tools/test_pwa.py`.


## Real timetable and "Meet faculty"

`tools/tt/build.py` turns the three aSc Timetables PDFs (room-wise, class-wise, faculty-wise) into `tools/tt/real_timetable.json`;
`tools/gen_data.py` then loads it into the NCU campus package (1,700+ weekly slots, 190+ teachers).

    python3 tools/tt/build.py <room-wise.pdf> <class-wise.pdf> <faculty-wise.pdf>
    python3 tools/gen_data.py

* Rooms are matched to the map (`RN 112` is Old Building 112, `N 205` is New Building N205). Rooms that are not drawn yet
  (CN block, N4xx, a few labs) keep their name, still count for the teacher, and show as text.
* The PDFs only carry short names (`Shruti.S`). Full names come from the CSE legends; two teachers who share a short name are kept apart where the files clash.
* **Meet faculty** tab: who is free now (or at a picked day and time), longest free time first, with what they are coming from and going to. A teacher's card lists
  their free windows for every day. Admins can set a cabin from the teacher's card; until then students are told where to look (near the last or next class).

## Login
The site opens on a login screen (`js/auth.js`). Sign in with a college email (`anything@ncuindia.edu`); the password is the part before the `@`, for example `23csu001@ncuindia.edu` with password `23csu001`. The session is kept for 30 days and can be ended from the account dialog ("Log out"). This check runs in the browser, so it keeps casual visitors out but is not real security. For real protection, put the site behind the university's own sign-in on the server. The UI tests sign in through `tools/_auth.py`.
